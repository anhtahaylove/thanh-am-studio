# Desktop/worker contract v1

All JSON fields are snake_case. Times are milliseconds except worker STT segments (seconds). IDs UUID strings. No HTTP server.

## Tauri commands (invoke)
- `list_projects` -> ProjectSummary[]
- `create_project({name})` -> Project
- `load_project({id})` -> Project
- `save_project({project})` -> Project (revision optimistic lock; increments revision)
- `delete_project({id})` -> void (`PROJECT_BUSY` while the project has queued or running jobs; otherwise deletes the project, its failed, cancelled and interrupted jobs and its succeeded `tts` jobs; other succeeded jobs stay, since other projects reuse separation stems by asset id, renders are saved from the queue and a transcript can be applied to another project; never deletes files or shared assets)
- `get_settings` -> AppSettings (defaults to `{dictionary:{}}`)
- `save_settings({settings})` -> AppSettings (validated: `dictionary` is an object of non-empty string keys to string values, at most 5000 entries, each at most 512 bytes; `worker_engines`, optional, is an object of operation (`tts|stt|render|download|clone_preview|separate`) to `auto|python`, kept as stored when absent; other fields are dropped)
- `list_jobs` -> Job[]
- `enqueue_job({kind,projectId,payload})` -> Job
- `cancel_job({id})`, `retry_job({id})` -> Job
- `runtime_status` -> RuntimeStatus
- `export_diagnostics({path})` -> void (an absolute `.txt` path; one UTF-8 file with the app version, CPU, the current settings, both worker logs and `startup-errors.log`, where a failed start is appended)
- `read_text_file({path})` -> string (TXT/SRT/VTT/CSV/DOCX only; text files are UTF-8 with BOM removed; a DOCX returns the plain text of `word/document.xml`: one line per paragraph, a table row on one line with non-empty cells joined by ", ", inserted text kept, deleted text, field codes, text boxes and `mc:Fallback` skipped; errors `INVALID_DOCX`, `DOCX_TOO_LARGE`, and `TEXT_FILE_TOO_LARGE` when the text passes 10 MB; DOCX files up to 100 MB, other files up to 10 MB; the command runs on a blocking thread; the bridge maps these codes to short Vietnamese messages)
- `import_asset({path})` -> Asset (copies to app data by hash, original untouched)
- `get_asset({id})` -> Asset (restore imported source playback)
- `list_models` -> ModelInfo[]
- `download_model({id, licenseAccepted?})` -> Job (`LICENSE_NOT_ACCEPTED` when the model is the separation runtime pack, it is not installed at the pinned revision and `licenseAccepted` is not `true`: the pack contains Intel oneMKL, whose licence the UI shows before it asks; re-checking an installed pack needs no consent)
- `export_text({path,content})` -> void (TXT/SRT/VTT/CSV only)
- `export_asset({assetId,path})` -> void (explicit native save dialog output)
- `export_asset_new({assetId,path})` -> boolean (copies like `export_asset` but never overwrites: `false` when `path` already exists; a failed copy removes the partial file; used by "save all chapters", which reports saved, skipped and failed files)
- `list_voices` -> Voice[]
- `save_voice({voice})` -> Voice (reference asset + consent boolean)

Use @tauri-apps/plugin-dialog for open/save dialogs; convertFileSrc(asset.path) for audio. Browser mode must label itself as preview; no fake inference successes.

## Data
ProjectSummary: {id,name,updated_at,revision}
Project: {id,name,updated_at,revision,segments: Segment[],transcript: TranscriptSegment[],dictionary: Record<string,string>,source_asset_id: string|null}
AppSettings: {dictionary: Record<string,string>} (app-wide pronunciation dictionary; TTS normalization applies `{...appDictionary, ...project.dictionary}`, so the project entry wins)
Segment: {id,text,normalized_text,voice_id:string|null,speaker:string,gap_ms:number,takes: Take[],selected_take_id:string|null,trim_start_ms:number,trim_end_ms:number|null,fade_in_ms:number,fade_out_ms:number,gain_db:number,cue_start_ms?:number|null,cue_end_ms?:number|null,chapter?:string|null}  // the subtitle cue a segment came from (SRT/VTT import or transcript to script); split shares it by text length, merge spans both; `chapter` is set only on the first segment of a chapter (a script line starting with `[P<digits>]`, any case, starts one and the marker is never spoken; or typed in the segment details), a segment belongs to the nearest chapter start at or before it and segments before the first one form `P0`; split keeps it on the first half, merge keeps the first segment's
Take: {id,asset_id,path,duration_ms,sample_rate,created_at,speech_start_ms?:number,speech_end_ms?:number|null}  // speech edges found by the worker; the segment trim is set to them when the server auto-selects the first take or the user selects a take (older takes have none: trim 0/null)
TranscriptSegment: {id,start_ms,end_ms,text,speaker:number|null,overlap_speaker:number|null}  // speaker only when the job diarized; overlap_speaker = another speaker talking over most of this row, else null
Asset: {id,path,name,duration_ms:number|null,sample_rate:number|null}
Voice: {id,name,kind:'preset'|'reference',reference_asset_id:string|null,consent:boolean,engine_voice_id:string|null}
Job: {id,kind,project_id:string|null,payload:object,status:'queued'|'running'|'succeeded'|'failed'|'cancelled'|'interrupted',progress:number,error:string|null,result:object|null,created_at,updated_at}  // a succeeded job's result carries `engine:'python'|'rust'` (the worker that produced it) and `fallback:boolean` (true when it ran on Python after the native worker failed)
RuntimeStatus: {python_ready:boolean,ffmpeg_ready:boolean,worker_ready:boolean,native_worker_ready:boolean,python_path:string|null,ffmpeg_path:string|null,native_worker_path:string|null,fallback_count:number,message:string}  // `fallback_count` = reruns on Python logged in worker-fallbacks.jsonl
ModelInfo: {id,name,engine,kind:'model'|'runtime',installed:boolean,revision:string,license:string,description:string}  // `kind` is `runtime` for `separation-runtime`, the downloadable Python + PyTorch + Demucs pack (`models.json` `pack`: url, size, unpacked_size, sha256, manifest_sha256, files, longest_path; `revision` names its `pack-separation-v<N>` release); its `installed` needs the marker's revision to equal the pinned one

## Client editing rules
- Undo/redo keeps at most 50 project snapshots taken per edit (typing within 1s collapses into one step) and is cleared when a project is opened, created, reloaded or deleted. Restoring a snapshot keeps the current `revision` and unions takes per segment id from the current project (a segment created after the snapshot that already owns takes is kept), so undo never removes a take the server added.
- Segment split: the first half keeps the id, takes and `selected_take_id`; the second gets a new id and no takes. Merge keeps the first segment's id and takes; the next segment's takes are detached from the project (assets stay on disk) after a confirmation.
- Transcript times are validated before they reach `save_project`: `start_ms >= 0` and `end_ms > start_ms`; invalid edits are rejected in the UI and STT results are clamped to this range.
- `stt` jobs are only enqueued when `list_models` reports the chosen whisper model as installed.
- On desktop window close with unsaved edits the UI flushes `save_project` first (capability `core:window:allow-destroy`); if saving fails the user may choose to close and discard.

## Job kinds and payloads
- tts: {segment_id,text,voice_id:string|null,reference_asset_id:string|null}; backend resolves voice/reference and model paths; result adds a new take without replacing existing selection (first take auto-selected only when none, with the segment trim set to its speech edges). Takes are append-only: adding one does not change the project revision, and save_project keeps stored takes the client has not seen (and, when the client has no selection yet, the stored selection with its trim).
- stt: {asset_id,model_id:'whisper-small'|'whisper-turbo',language:'vi'|'auto',diarize?:boolean,num_speakers?:1..8|null,min_speakers?:1..8|null,max_speakers?:1..8|null}; the speaker counts are whole numbers 1..8 and only used with `diarize`; `num_speakers` (exact count) excludes `min_speakers`/`max_speakers` (an allowed range for the automatic count, min <= max); a bad value or a mix is rejected with INVALID_SPEAKERS; result transcript must not silently overwrite edited transcript: retain result on job, UI applies explicitly.
- render: {segments:Segment[],normalize:boolean,format:'wav'|'mp3'|'m4a'|'flac'|'opus',timeline?:boolean,pad_to_ms?:number,background_asset_id?:string,name?:string,batch?:string,batch_size?:number} (`name`/`batch`/`batch_size` are only carried in the job payload: a per-chapter export enqueues one render job per chapter, named like `001-P1`, all sharing one `batch` id, and each carries `batch_size`, the number of jobs the export meant to enqueue, so a batch cut short by a failed enqueue is never offered as complete; the backend ignores all three); with `timeline` every segment also carries `dub_at_ms` (0..86,400,000) and `dub_rate` (1..2) from the app's dub plan (`dubPlan` in src/domain.ts) and `pad_to_ms` is required, else INVALID_TIMELINE; `background_asset_id` (the stem asset of a succeeded `separate` job of the project's `source_asset_id`, chosen by the app when "Giữ nhạc nền" is on) is accepted only with `timeline` and an existing asset, else INVALID_BACKGROUND, and is forwarded as `background_path`; backend resolves selected takes by asset IDs, ignores untrusted payload paths. Output is a new asset.
- model_download: {model_id, license_accepted_at?}; download pins manifest revision and verifies cached content. For `separation-runtime` (the pack): `license_accepted_at` (set by `download_model` from `licenseAccepted`) is required to install and is recorded in `installed.json`; the worker downloads the pack zip (resumable, pinned size and SHA-256), checks the manifest against its pin, refuses names that leave the folder or are not in the manifest, checks that the folder plus the longest manifest path fit 259 characters (`PACK_PATH_TOO_LONG`: "Đường dẫn thư mục dữ liệu quá dài nên không cài được gói tách nhạc nền."), extracts straight into `models/separation-runtime/` hashing every file, and writes `installed.json` last. A job for an installed pack of the pinned revision only re-hashes the tree against `MANIFEST.sha256` and reports files that are not in it (`MODEL_CHECKSUM`; the marker is removed so the pack is offered again); another revision replaces the old tree. `MANIFEST.sha256` lists every other file as `<sha256>  <size>  <path>` (`/` separators, sorted).
- clone_preview: {asset_id,name?,version?}; backend resolves the sample asset and the vieneu-v3 model path (payload paths are ignored; `name` labels the queue row and `version`, the app version, is only carried in the payload); output is a new asset: the sample as VieNeu enrolls it for cloning. No consent is needed (nothing is cloned); the button needs vieneu-v3 installed. The UI reuses a succeeded clone_preview job with the same `asset_id` and `version` and plays its result when it ends if the voice form still shows that sample. Queued clone_preview jobs are claimed before other queued work (`claim_next`).
- separate: {asset_id,name?}; `name` labels the queue row; the backend resolves the asset and the installed `htdemucs` model, ignoring payload paths. Result: the background (every HTDemucs source but the vocals) as a new 44.1 kHz stereo 24-bit FLAC asset. A separation job runs on the pack's own `python.exe` (`-B -I -X utf8`, so nothing is written into the pack), never on the installer's runtime: `MODEL_NOT_READY` ("Chưa có gói chạy tách nhạc nền. Kết nối mạng rồi bấm Tải.") when the pack is missing or of another revision, `MODEL_CHECKSUM` when the manifest is not the pinned one or a listed file is missing or has another size. Queued separations run after all other queued work (`claim_next` orders by `kind<>'clone_preview'`, `kind='separate'`, then `created_at`); a running one still holds the worker until it ends. Cancel kills the worker; after a separation ends in any state its job folder keeps only `worker.log` (the stem is imported or is a partial); one cut off by a crash is cleaned when the store reopens and marks it interrupted.

## Worker JSON-lines protocol
One process per job, one JSON request on stdin, UTF-8 JSON events on stdout; diagnostics stderr. Request: {protocol:1,id,operation:'tts'|'stt'|'render'|'download'|'clone_preview'|'separate'|'probe'|'health',payload:object,output_dir,models_dir}. Output: {protocol:1,id,event:'progress',progress:0..1,message?} or {protocol:1,id,event:'result',result:object} or {protocol:1,id,event:'error',code,message}. Exit nonzero on failure. Never report a result before atomic output finalization. Exactly one terminal event ends a run: `result` then exit 0, or `error` then exit 1, and the native worker ends its process (`TerminateProcess`) right after flushing it; a panic emits `error {code:'RUST_PANIC',index?}`, never `result`.

Worker tts payload {text,voice_id?,reference_path?,model_path,output_name}; every text is non-empty, at most 100,000 characters, and has no run of more than 600 characters without whitespace (`MAX_TOKEN_CHARS`, Python `str.split()` tokens), else the request ends with INVALID_TEXT; result {path,duration_ms,sample_rate,speech_start_ms,speech_end_ms}: the first/last sample above max(1e-3, 2 % of peak) with an 80 ms margin (`EDGE_MARGIN_S`), speech_end_ms null when it reaches the end; a pause mark at the very start or end keeps that edge.
Worker tts batch payload {model_path,items:[{text,voice_id?,reference_path?,output_name}]}: the engine loads once; each item reports {protocol:1,id,event:'item',index,result:{path,duration_ms,sample_rate}} or {...,event:'item',index,error:{code,message}}; a failed item does not stop the batch; final result {count}. The desktop batches up to 32 queued tts jobs per worker process.
Worker stt payload {input_path,model_path,language:'vi'|'auto',diarize_model_path:string|null,num_speakers:number|null,min_speakers:number|null,max_speakers:number|null} (the last four are null when the job does not diarize); result {segments:[{start,end,text,speaker?,overlap?}],language,diarize_error?}. `overlap` (only present when set) is the id of another speaker whose turns cover at least `OVERLAP_SHARE` (0.5) of that segment's time; the desktop copies it to the transcript row as `overlap_speaker` (null when absent). `diarize.py` runs the diarization in a child process (`diarize_isolated`), so a native crash there ends in `diarize_error` and the plain transcript instead of a lost job.
Worker render payload {clips:[{path,trim_start_ms,trim_end_ms,gap_ms,fade_in_ms,fade_out_ms,gain_db,at_ms?,rate?}],normalize,format ('wav'|'mp3'|'m4a'|'flac'|'opus'),ffmpeg_path?,timeline:boolean,pad_to_ms:number|null,background_path?:string|null}; with `timeline` each clip starts at `at_ms` (silence fills the wait, never earlier than the previous clip's end), is sped up by `rate` (FFmpeg atempo), `gap_ms` is not used, and the output runs at least to `pad_to_ms`; with `background_path` (only with `timeline`, else INVALID_BACKGROUND) the mono dub goes to both channels (`pan`) and is summed at 0 dB with the background from sample 0 (`amix` `normalize=0`, `duration=longest`: a longer background runs the output to its end, a shorter one stops while the dub goes on; no loop, stretch or fade), then, with `normalize`, given one constant gain to -16 LUFS measured over the whole mix in a first FFmpeg pass (not loudnorm's dynamic single pass, which would swell the background between lines), and always passed through a latency-compensated limiter at 0.98; the output is stereo; result {path,duration_ms,sample_rate}.
Worker download payload {model_id}; result {model_id,path,revision}.
Worker clone_preview payload {reference_path,model_path,output_name}; the same steps a cloned tts enrolls the reference with: `clone_reference` (the best 8 s), VieNeu's `_preclean_reference_audio` (edge silence trim), its first `_MAX_REF_SECONDS` and its `OnnxDenoiser` (`backbone/denoiser.onnx`); result {path,duration_ms,sample_rate:44100}, a PCM_24 WAV. A missing reference is INPUT_MISSING. `test_vieneu_pin_was_verified` fails when the vieneu pin changes until the real-model equivalence test is rerun.
Worker separate payload {input_path,model_path,ffmpeg_path?,output_name}; result {path,duration_ms,sample_rate:44100,channels:2}. Before loading the model it needs 1.5 GB of free RAM and 2.5 GB of free commit (`LOW_MEMORY`) and free disk for twice the 24-bit stem plus 256 MB (`DISK_FULL`); a weights file whose metadata names another class than `demucs.htdemucs.HTDemucs` is refused (`MODEL_UNKNOWN`). FFmpeg decodes the input once to 44.1 kHz stereo; HTDemucs (`shifts=0`, 8 threads) runs on 60 s windows sharing 2 s, crossfaded linearly; progress follows the model's segments. Only this operation imports torch.
Worker health payload {profile?:'base'|'separation'} (default `base`; another value is INVALID_REQUEST) and result {python,profile,modules,torch_imported_by_engines,ffmpeg,ready}: `base` (the installer's runtime) needs numpy, soundfile, onnxruntime, ctranslate2, av, vieneu, faster_whisper and huggingface_hub to import and `torch_imported_by_engines` (torch loaded by importing the engines) to be false; `separation` (the pack's python) needs numpy, soundfile, torch, `demucs.htdemucs` and safetensors.

## Worker engines
- `worker	hanham-worker.exe` (Rust, protocol v1, same codes and messages) serves the operations in `RUST_OPS` (`src-tauri/src/engine.rs`). The user can send any operation back to Python with `worker_engines`; every change is logged in `worker-engine-changes.jsonl` (time, version, operation, from, to).
- Each worker runs in a job object of its own, nested in the app's: cancel and app exit call `TerminateJobObject`, so what a worker started dies with it.
- A received `result` of the native worker is final whatever its exit code; a later crash is logged as `exit_after_result`. Two results are not final: a tts item error with `WORKER_ERROR`/`RUNTIME_MISSING` (that item reruns) and an stt result with `diarize_error_code:'DIARIZE_PROCESS'` while speakers were requested (the whole job reruns). `MODEL_*` diarize codes keep the transcript without speakers and `diarize_error`.
- Fallback-eligible before a `result`: `RUST_PANIC`, a terminal `error` with `WORKER_ERROR` or `RUNTIME_MISSING`, and an exit without `error` with code `0xC0000135`, `0xC0000005`, `0xC000001D`, `0xC0000409`, `0xC00000FD` or `101`. Not eligible: any other code, protocol errors, out of memory (`0xC0000017`).
- The rerun happens once per job, on Python, with only what was not reported (a tts batch reruns its pending items through the index path); every file in the job folder except `worker.log` is deleted first, and `worker.log` gets a separator line. Each eligible event adds a line to `worker-fallbacks.jsonl` (time, version, operation, code, exit, CPU brand and ISA, cloned take, action `rerun` or `exit_after_result`).

Resources: worker directory distributed as Tauri resources; Python/FFmpeg resolved from the bundled resource runtime (runtime/python, runtime/ffmpeg); release builds never use the source checkout, PATH or env vars. Debug builds may fall back to the source tree and THANHAM_PYTHON / THANHAM_FFMPEG. The worker runs as python -I -X utf8 with THANHAM_FFMPEG/THANHAM_FFPROBE set to the bundled binaries. Missing runtime/model yields actionable error, never placeholder audio.
